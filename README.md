# flytegral

A connectome-driven experimental agent built around the **MaleCNS / Drosophila neural graph**.

The current project explores whether a fixed biological recurrent substrate can be given trainable sensory/readout interfaces and used as an autonomous mathematical text policy. Its first public application is **Fly Tweets**: an English-language X account whose text and publication cadence are generated by the fly system itself.

> No LLM participates in runtime tweet generation, filtering, ranking, reward assignment, vocabulary expansion, or daily training.

## Fly Tweets

The fly controls two things directly:

- **what to say** — autoregressive token generation from the connectome-driven policy;
- **when to say it** — a learned cadence policy chooses both the number of tweets and each exact publication time.

The publication pipeline is deliberately separated from the author:

```text
MaleCNS policy
    ↓
Durable local outbox + rows.json
    ↓
Hidden Windows native-X task
    ↓
Verified X / Twitter permalink
```

The durable local state is the source of truth. A hidden Windows task checks the native delivery queue every 15 minutes and verifies the published text on X before recording success. The legacy Sheet/Buffer path is excluded from the production orchestrator.

The sender retains the fly-selected publication times, prevents duplicate sends, and records delivery uncertainty for reconciliation. Posts more than six hours late are marked missed rather than published unexpectedly.

## Learning loop

After publication, a headless DOM collector reads X engagement metrics such as:

- views
- likes
- replies
- reposts
- bookmarks

Eligible observations feed conservative reward-driven updates. Text reward and cadence reward are tracked separately so scheduling mistakes do not incorrectly punish language generation.

A successful daily cycle:

1. reconciles publication state;
2. collects eligible X metrics;
3. updates text and/or cadence policies when training data exists;
4. checkpoints the new state;
5. samples the next fly-owned publication horizon;
6. appends the new rows to the durable Sheet backlog.

## Runtime

Heavy work runs on a Windows self-hosted GitHub Actions runner. A lightweight default-branch GitHub orchestrator keeps the process durable across PC-offline periods.

Normal operation is headless: no terminal, browser window, Python console, or confirmation dialog should appear on the desktop.
